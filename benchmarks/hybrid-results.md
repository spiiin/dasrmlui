# Hybrid DataModel: повторный бенчмарк

Реализован opt-in runtime: native DataModel/DataViews обслуживают прямые scalar-привязки,
макросы уведомляют о записях, компоненты и `each_keyed` сохраняют управление структурой.
[API и ограничения](../docs/hybrid.md), [воспроизводимая методика](README.md).

## Условия и границы

Intel Core i9-14900HX, Windows build 26200, Intel RaptorLake-S Mobile Graphics Controller,
GL 3.3 driver 32.0.101.6881. MSVC 19.38 x64 Release, RmlUi 6.4-dev; интерпретатор daScript.
Окно 800×700, DPI 1, невиртуализированный список; swap/present не измеряется.
Для каждого сценария и движка: 4 раунда × 120 измерений после 30 прогревочных кадров,
затем отдельный раунд памяти. Порядок трёх движков циклически меняется.
Сборка, тесты и другие benchmark-процессы не запускались параллельно измерениям.
Частоты CPU не фиксировались; абсолютные времена зависят от окружения.

Теперь отдельно измеряется **mutation**: изменение модели и уведомления о записи.
**Prepare = mutation + bindings**, сумма вычисляется для каждого кадра до median/p95.
Так стоимость уведомлений hybrid не оказывается за границей сравнения.
Исторический [baseline](results.md) не содержит mutation; ниже все три пути измерены заново.

Native reference помечает dirty корень `rows`, hybrid — отдельную переменную привязки.
Это разные гранулярности обновления, а не доказательство превосходства daScript над C++.
При rotate DSL/hybrid сохраняют keyed identity; native `data-for` обновляет позиции.
Render CPU, остаточное ожидание GPU (`glFinish`) и GC показаны отдельно.
Сумма медиан фаз не является медианой полного кадра.

## Практический результат

- Подготовка изменения одного поля при N=1000 ускорилась примерно в **295 раз** относительно legacy DSL в этом запуске. Это ускорение подготовки, не полного кадра.
- Hybrid не выполняет обход компонентного дерева на быстрых idle/single/bulk путях. Smoke подтверждает 0/1/N вызовов native getter-ов соответственно.
- В этих трёх сценариях нет логических выделений daScript внутри Prepare. В single остаются небольшие native allocations; layout и render всё ещё выделяют память.
- Массовое обновление оплачивает N уведомлений. Перестановка остаётся структурным проходом с keyed diff, перестройкой подписок и временными выделениями.
- Изменение текста по-прежнему может запускать layout всего списка. Гибрид не устраняет стоимость Context::Update и отрисовки.
- Непрозрачные UI helpers, временные источники и сложные структурные операции сохраняют консервативный проход; приведённые цифры относятся к прямым scalar-привязкам.

## Проверки и артефакты

**84/84 CTest прошли**. После финального исправления обратных событий checked/value
повторно прошли все 6 затронутых тестов, включая расширенный checkbox-тест и benchmark smoke.
Отдельные тесты покрывают одинаковые записи, точечные dirty-привязки,
ввод и отклонённые изменения, условные узлы/атрибуты, ключи и перестановки, lifecycle,
локальное состояние, GC, переиспользование native slots, ui_watch и fallback для helpers.
Smoke проверяет порядок и текст DOM, identity при rotate и отсутствие предупреждений.
Smoke-снимки (N=32) всех четырёх сценариев DSL/native/hybrid совпали пиксель в пиксель (RGB).
