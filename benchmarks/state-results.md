# Managed state: повторный бенчмарк

Измерение 2026-11-13 после включения hybrid по умолчанию. `mode=2` использует
`[ui_component]`, `ui_state`, `ui_edit`, `ui_frame` и tracked helper `[ui_action]`.
Стоимость edit-блока и уведомлений входит в mutation. Legacy сохранён явно:
`[ui_component(legacy=true)]` и `ui_legacy_frame`. [API](../docs/hybrid.md).

Проверки: **93/93 CTest passed**, включая package, pixel checks и benchmark smoke;
все 22 примера прошли smoke. [Лог полного прогона](results/2026-11-13-state/ctest.log).

## Условия и ограничения

Intel Core i9-14900HX, Windows build 26200, Intel RaptorLake-S Mobile Graphics,
OpenGL 3.3 driver 32.0.101.6881; MSVC 19.38 x64 Release. daScript работает в
интерпретаторе. Окно 800×700, DPI 1, невиртуализированный список.
Для каждого пути/сценария: 4 раунда × 120 измерений после 30 прогревочных кадров,
затем отдельный раунд памяти. Порядок путей циклически меняется. Тесты и сборки
не выполнялись параллельно измерениям; частоты CPU не фиксировались.

**Prepare = mutation + bindings**, сумма вычисляется для каждого кадра перед
median/p95. Холодное создание и clone `ui_state` исключены; исходный массив
hybrid-модели очищен до измерений. Update, Render CPU, остаточное ожидание GPU
(`glFinish`) и принудительный GC измерены отдельно. Swap/present не измеряется.

Native reference помечает dirty весь `rows`; managed hybrid использует отдельные
переменные привязок. Это сравнение схем с разной гранулярностью, а не daScript
против C++ при одинаковом алгоритме. При rotate legacy/hybrid сохраняют keyed
identity; native `data-for` обновляет позиции. GC относится ко всему script Context.
Сумма медиан фаз не является медианой полного кадра.

## N=100 и предыдущий hybrid

Медианы Prepare, миллисекунды.

| Сценарий | N=100 legacy | N=100 native | N=100 managed | N=1000 прежний hybrid | N=1000 managed |
|---|---:|---:|---:|---:|---:|
| Простой | 0.338 | 0.002 | 0.016 | 0.011 | 0.009 |
| Одно поле | 0.943 | 0.040 | 0.017 | 0.029 | 0.019 |
| Все поля | 1.282 | 0.094 | 0.124 | 1.060 | 0.687 |
| Перестановка | 1.333 | 0.083 | 0.986 | 7.651 | 3.790 |

Последние два столбца — разные запуски, без фиксации частоты/нагрузки системы;
их различия нельзя целиком приписывать изменению runtime. В текущем прогоне заметен
разброс времени: например, у hybrid bulk p95 Prepare — 6,465 мс при медиане 0,687 мс.
Поэтому медианы не следует воспринимать как гарантированное время кадра. Для сравнения схем
используйте три пути из текущего запуска. Перестройка keyed-списка всё ещё требует
структурного обхода и временных выделений; новый API не делает её точечной.
